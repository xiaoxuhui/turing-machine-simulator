# 图灵机实验台：关卡重置与撤销需求与测试用例

## 文档状态

- 目标版本：v0.5.1
- 状态：实施中
- 日期：2026-10-03
- 实施策略：只改动关卡页与其进度模型，不改变自由实验、项目 JSON v1、安卓外壳与关卡内容本身

## 目标

玩家在关卡页可以**重置本关草稿**、**撤销本关的通关状态**，并且撤销之后**不会失去已经走到的关卡**。

两项能力都只作用于"当前选中的关卡"，不影响其它关。

## 用户流程

1. 在「编写规则」区新增「重置本关」按钮：点击弹出页内确认；确认后把规则编辑器恢复为本关**初始提示**（`starter.rules`），并删除该关在本地保存的草稿。
2. 已经通关的关卡，在标题区显示「撤销通关」按钮：点击弹出页内确认；确认后该关回到「学习中」，从完成集合中移除。
3. 撤销通关后，玩家**此前已经能够进入的关卡不会被重新锁上**（见下方"解锁规则"）。
4. 两项操作都即时写入 `turing-machine-simulator.campaign.v1`，刷新页面后仍然生效。

## 解锁规则改动（前沿式）

原规则：第 N 关可进入 ⟺ 第 N 关之前的**每一关**都已完成。

问题：撤销中间某一关会在完成集合里留下空洞，按原规则会把玩家**已经走到的后续关卡全部重新锁死**。

新规则：**第 N 关可进入 ⟺ N 的序号 ≤ 最远已完成关的序号 + 1**。

- 初始：只可进入第 1 关。
- 完成第 1 关后：第 2 关可进入（与原规则一致）。
- 已完成 1–5 关后撤销第 3 关：第 3、4、5 关仍可进入，第 6 关仍可进入。
- 该公式仍然保证"一次只能推进一关"，不会允许跳关。

## 单元测试用例

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| U01 | 重置有草稿的关卡 | 该关草稿被删除；再次读取回落为该关 `starter.rules` |
| U02 | 重置本关 | 其它关的草稿与完成集合不受影响 |
| U03 | 重置从未编辑过的关卡 | 返回同一对象（no-op） |
| U04 | 撤销已完成关卡 | 该关从 `completedLevelIds` 移除 |
| U05 | 撤销未完成的关卡 | 返回同一对象（no-op） |
| U06 | 撤销未收录的关卡 id | 返回同一对象（no-op） |
| U07 | 前沿式解锁：撤销后不锁死后续 | 完成 1–5 关后撤销第 3 关，第 4、5、6 关仍可进入 |
| U08 | 前沿式解锁：基本顺序 | 初始只解锁第 1 关；完成第 1 关后解锁第 2 关 |
| U09 | 前沿式解锁：不得跳关 | 只完成第 1 关时，第 3 关仍不可进入 |
| U10 | 未知关卡 id | 一律 `false` |
| U11 | 撤销后可重新通关 | 撤销第 N 关后，`completeLevel` 能再次把该关加入完成集合 |
| U12 | 含空洞的旧进度 | `normalizeCampaignProgress` 与 `isLevelUnlocked` 均不抛错 |

## 非目标

- 不做运行态撤销（单步回退 / 纸带回滚）——本次只做草稿与进度的撤销。
- 不做编辑器逐字符撤销栈（桌面端继续使用浏览器原生 `Ctrl+Z`）。
- 不提供关卡答案载入、不改变关卡内容与参考答案。
- 不改变进度存储格式（仍为 `CampaignProgress.version = 1`）。
- 不发布、不打标签、不推送；发布由用户另行授权。
