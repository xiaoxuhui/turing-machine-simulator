# 图灵机实验台：关卡模式设计

## 文档信息

- 目标版本：v0.4.1
- 状态：已确认，实施中
- 日期：2026-09-27

## 设计目标

1. 关卡目标与验证规则由纯数据描述，便于增加关卡和独立测试。
2. 验证器创建临时 `TuringMachine`，绝不修改页面正在调试的实例。
3. 进度模型只保存已完成关卡 ID；解锁状态由顺序推导，避免缓存矛盾。
4. 关卡使用独立 HTML 入口和独立页面状态，不复用自由实验项目，也不提供载入答案路径。
5. 教程把复杂目标拆成单概念递进关卡，并以步骤而非完整规则指导。

## 模块边界

- `src/campaign.ts`
  - `campaignLevels`：关卡目标、教程步骤、空白草稿、公开测试与步数上限。
  - `verifyLevel()`：批量运行临时机器并返回结构化结果。
  - `normalizeCampaignProgress()`、`completeLevel()`：过滤进度、推导解锁。
  - `tapeOutput()`：按非空单元最小/最大位置生成规范输出。
- `campaign.html` + `src/campaign-main.ts`
  - 独立关卡页面、专用规则编辑器、示例试跑、提交验证和进度/草稿存储。
- `src/campaign-styles.css`
  - 教程、关卡导航、编辑区、纸带结果和移动端布局。
- `src/main.ts`
  - 只提供进入关卡页面的链接，不读取或修改关卡状态。

依赖方向为 `core.ts → campaign.ts → main.ts`。`campaign.ts` 不访问 DOM、localStorage 或全局页面状态。

## 数据模型

```ts
interface CampaignLevel {
  id: string;
  title: string;
  objective: string;
  concept: string;
  starterRules: string;
  lesson: { explanation: string; steps: string[]; syntax: string[] };
  cases: Array<{ input: string; expectedOutput: string }>;
  maxSteps: number;
}

interface CampaignProgress {
  version: 1;
  completedLevelIds: string[];
}
```

验证结果包含总数、已通过数、逐项输入/期望/实际、停止原因和步数。只要一项达到步数上限或输出不符，关卡失败。

## 界面

- 主实验台工具栏增加“进入关卡”链接；关卡页提供“返回实验台”。
- 关卡页显示总体进度、关卡导航、概念讲解、分步任务、语法卡、专用规则编辑器、示例试跑和验证按钮。
- 锁定关卡使用禁用样式和锁图标；完成关卡显示勾选。
- `aria-live` 结果区域播报试跑和验证结果。
- 构建采用 Vite 多页面入口，同时输出 `index.html` 与 `campaign.html`。

## 错误与兼容

- 当前机器定义无效时复用编辑器错误，并在关卡结果提示先修正规则。
- 进度 JSON 解析失败、版本错误或包含未知 ID 时安全过滤；保存失败不影响本次通关结果。
- 旧 localStorage、项目 JSON v1、快捷键和安卓静态资源同步脚本保持兼容。

## 测试策略

- Vitest 覆盖 8 关参考方案、错误输出、超步、输出规范化、解锁与损坏进度。
- 完整测试和生产构建验证既有 70 项回归。
- 真实浏览器覆盖模式切换、锁定、首关通关、失败反馈、刷新恢复以及桌面/移动布局。
