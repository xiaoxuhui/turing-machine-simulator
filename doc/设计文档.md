# 图灵机模拟器设计文档

## 高速直接移动（2026-10-26）

沿用 `slideDurationMs` 作为动画策略入口，区分手动单步和连续运行：单步固定 180ms，与目标速度无关；仅连续运行在目标速度 >10 时返回 0，低速及无效值回退沿用原行为。渲染层对 0 时长直接定位，清除旧 transition/transform，不做测量格距或强制重排。运行及单步按钮只设置动画来源，不修改计算或调度算法。固定/自由视角保留原拖动偏移逻辑。

## 除法及高阶运算设计（2026-10-24）

状态：已实现并验证。编译器为 `src/register-tm.ts`，运算程序为 `src/hyperoperation-examples.ts`；证据见 [高阶运算测试报告](高阶运算测试报告.md)。

以有限寄存器程序描述重复减法、重复乘法及高阶迭代，再编译成普通单纸带规则；引擎无新指令。每个寄存器为一段一进制，分隔符 | 存在原输入左侧，以 # 固定原点。加一通过逐格移位插入 1；减一/零分支通过逐格移位删除 1；所有跳转、复制与递归层级展开均形成有限状态。输入转移规则将两个操作数搬入寄存器，运行时执行循环，停机前擦除工作寄存器和原点，仅保留输出。字母表不使用寄存器位图，避免随寄存器数指数增长。乘方以上的有限层级在编译时展开程序结构，但不展开数据或预计算数值。超幂/超超幂采用从 1 开始迭代上一层运算的定义。

## 目标速度持久化修复（2026-10-24）

目标速度作为小型独立偏好存储，启动优先用有效偏好，再回退项目速度。调速同步提供回调，立即写偏好，不触碰当前机器、规则或执行状态，也不反复序列化大项目。项目显式填充（包括导入）同步更新偏好；数列转换在填充前保留当前速度。无效存储值忽略，存储异常返回提示。

## 一进制示例扩充设计（2026-10-24）

沿用 `ExampleProject` 与原有单纸带核心；示例全部由普通转移规则执行，不添加运算捷径。加法合并两段后删除多余分隔位；减法以 X/Y 逐对标记并清理；乘法逐个标记左操作数并反复复制右操作数到结果区，最后清除操作数和标记；比较逐对消去并清理输出单个比较符号；整除 2 通过两个状态交替判断奇偶。乘法的结果留在原输入右侧，读写头停在结果首格。零以空串表示，不写字符 0。二元格式只约定一条分隔符，两侧仅有 1，不引入通用表达式解析器。现有示例选择器从记录自动生成，新增数据即出现入口。

扩展：示例拆到一进制、忙碌海狸、猜想三个模块，主记录聚合；可选 category 和 maxSteps 分别用于分组和长机器默认步数。忙碌海狸按研究项目给出的普通转移表录入（状态数不含停机态，符号数含空白 0），不计算最优性。哥德巴赫示例限制输入为不大于 100 的偶数，先验证输入长度和奇偶，再把纸带分成候选 p、q；对 2..10 的每个试除数用有限状态累计余数，实际扫描纸带判断素数（候选等于试除数时保留素性），失败则移动分隔符尝试下一分拆，不预存素数表或答案。考拉兹以二进制原地计算，奇数分支从右到左按 n+2n+1 处理进位，偶数分支删除末尾 0。两例只报告给定输入的验证结果。

## 吉斯维杰特数列 TM 设计补充（2026-10-24）

这不是 JavaScript 在运行时生成数列的模式。转换器只根据阈值 `T` 生成有限状态和有限字母表的转移规则，输出到已有规则编辑器；随后现有单纸带 `TuringMachine` 逐步执行。`0` 为空白，结果项用正整数字符串作为单格符号（解析器允许多字符符号），工作标记与结果数字必须可区分。纯 TM 规则必须实现：枚举后缀块长、比较相邻重复块、更新最大重复次数、写入新项、判断 `newTerm > T`。达到阈值时不能停。转换器不得以预先算好的数列前缀生成状态链。编译阶段只允许展开有限字母表/状态模板，不允许调用数列求值函数。

验收时不仅检查最终数字，还要检查规则文本可解析、执行中有实际工作标记/回扫、数列前缀没有嵌入转换器代码，并用独立参考算法核对结果。大阈值可能使运行步数或首现位置极大；界面不得承诺短时间完成。

实现细节：用四个标记位 O/S/A/B 编码原候选块起点、当前块起点和左右比较游标；纸带左侧 `#b` 保存本轮最佳重复次数。比较游标逐格左移，每完成一个块再增加计数。候选块起点每轮左移一格。首次检测到 T+1 个重复块时，可写出 T+1 并停机：若当前前缀末尾为 Y^k，删去最后一个符号后仍有某个旋转块重复 k-1 次，所以沿数列的卷曲数最多上升 1；首个超过 T 的数必为 T+1。转换支持 0–16，以控制有限字母表展开所占内存，不限制运行步数或输出项数。结构化规则表分页显示 100 条，编辑保留注释和其它页规则。

双模式补充：用户要求同时保留直接计算。模式选择仅切换两个面板的可见性。直接模式用纯数列函数和独立 Worker 计算，控制器持有数列数组；机器模式继续由现有图灵机实例持有纸带与执行状态，两者不互写。直接模式的取消/重置会终止对应 Worker，回调必须检查 Worker 身份，避免旧任务回调污染新结果。

## v0.2.0 重构设计补充（2026-08-27）

### 目标

本轮保持核心模型和页面行为兼容，优先消除路线 Worker 崩溃路径，并从 `main.ts` 提取两个可独立测试的边界：

依赖方向固定为：纯函数/核心类型 → 控制器 → `main.ts` 页面装配。控制器不解析规则、不创建机器定义，也不直接持有项目草稿。

- 保留现有项目 JSON v1 与本地缓存键。

- 保留全路线的后台生成、取消和最多约 2400 行可视采样。
- Worker 的失败必须成为可恢复 UI 状态，不允许按钮永久禁用。

### 测试策略

- 纯函数用 Vitest 覆盖边界和大数组。
- 控制器通过注入 Worker 工厂与回调进行生命周期测试。
- 最终在真实浏览器覆盖运行/暂停、1000 步/秒、路线完成/取消、桌面和窄屏布局。

## 4. 核心领域模型

### 4.1 基本类型

```ts
type StateId = string;
type TapeSymbol = string;
type Direction = "L" | "R" | "N";

interface Transition {
  fromState: StateId;
  readSymbol: TapeSymbol;
  toState: StateId;
  writeSymbol: TapeSymbol;
  direction: Direction;
}

interface MachineDefinition {
  states: StateId[];
  inputAlphabet: TapeSymbol[];
  tapeAlphabet: TapeSymbol[];
  blankSymbol: TapeSymbol;
  initialState: StateId;
  acceptStates: StateId[];
  rejectStates: StateId[];
  haltStates: StateId[];
  transitions: Transition[];
}
```

接受、拒绝和普通停机状态分别保存，但运行引擎统一将它们视为终止状态，再由界面呈现不同结果。

### 4.2 稀疏纸带

纸带使用 `Map<number, TapeSymbol>` 保存非空白单元：

```ts
interface TapeSnapshot {
  cells: Array<[number, TapeSymbol]>;
  headPosition: number;
}
```

- 读取不存在的位置时返回空白符。
- 写入空白符时删除该位置，保持数据稀疏。
- 逻辑位置使用安全整数；首版不支持超出 JavaScript 安全整数范围的运行。
- UI 只渲染一个有限窗口，纸带模型本身不受窗口范围限制。

### 4.3 规则索引

运行前将规则编译为二级映射或复合键映射：

```text
state + separator + symbol -> transition
```

构建索引时检测重复键。符号和状态允许包含普通字符，因此内部复合键不能用用户可输入的简单分隔字符串直接拼接；建议使用嵌套 `Map<StateId, Map<TapeSymbol, Transition>>`。

### 4.4 运行配置

```ts
interface RuntimeConfiguration {
  currentState: StateId;
  headPosition: number;
  tape: Tape;
  stepCount: number;
  status: "ready" | "running" | "paused" | "halted" | "error" | "limit";
  stopReason?: StopReason;
}
```

每次执行必须是原子的：读取、匹配规则、写入、移动、切换状态、递增步数，然后检查终止状态。

## 5. 单步执行流程

```text
用户触发单步
  → 检查机器定义是否有效
  → 检查当前状态是否已经是终止状态
  → 从纸带读取当前符号
  → 查找 (当前状态, 当前符号) 规则
  → 无规则：以 missing-transition 原因停止
  → 写入符号
  → 移动读写头
  → 更新状态
  → 步数 +1
  → 检查接受/拒绝/停机状态
  → 生成步骤记录与界面更新事件
```

引擎的 `step()` 不直接操作 DOM，也不显示弹窗，只返回结构化结果。

## 6. 连续运行调度

不采用一次性同步循环执行全部步骤，否则大程序会阻塞页面。建议分两种模式：

- 可观察速度：按用户设定间隔执行，每步或每少量步刷新界面。
- 高速模式：按时间片批量执行，例如每批最多若干百步或不超过约 8–12 毫秒，然后把控制权交还浏览器。

调度器职责：

- 接收运行、暂停和速度变化。
- 每批检查暂停标志和步数上限。
- 合并非关键界面刷新，保证按钮仍可响应。
- 运行结束后强制渲染最终状态。

首版可先在主线程使用时间片；只有性能测试证明必要时才引入 Web Worker。核心引擎无 DOM 依赖，因此后续迁移到 Worker 不需要重写算法。

## 7. 状态管理

工作台状态分为三层：

1. 草稿定义：用户正在编辑的配置和规则，可能暂时无效。
2. 初始快照：点击运行或重置时使用的有效初始配置。
3. 运行配置：当前纸带、状态、头位置、步数和日志。

草稿发生变化时，不直接悄悄修改正在运行的机器。若用户在暂停状态编辑程序，界面应提示需要重置后应用，避免“显示的是新规则、执行的是旧规则”的混乱。

## 8. 规则文本格式

### 8.1 首版语法

```text
# 注释
q0,1 -> q0,1,R
q0,□ -> HALT,1,N
```

- 每行一条规则。
- 空行和以 `#` 开头的行忽略。
- 箭头两边允许空格。
- 首版状态名和符号不允许包含逗号、换行或 `->`。
- 符号必须恰好是一个 Unicode 字素簇，而不是简单限制为一个 UTF-16 代码单元。
- 方向大小写归一化为 `L/R/N`。
- 解析错误包含行号、列或字段及可读提示。

### 8.2 表格同步

表格和文本不进行逐按键双向覆盖。建议把文本编辑放在独立模式中：

- 进入文本模式时由有效表格生成文本。
- 用户点击“应用”后整体解析。
- 解析成功才替换结构化规则。
- 解析失败保留文本草稿和原结构化规则。

这样可以防止编辑半行规则时破坏当前机器。

```json

  "name": "一进制加一",
  "machine": {},
```

## 10. 本地存储

- 使用单一带版本号的本地存储键保存最近项目。
- 写入采用防抖，避免每次按键同步写盘。
- 运行中的每一步不持久化完整纸带；只持久化编辑定义和初始配置，必要时在暂停/停止时保存当前会话快照。
- 读取失败或数据损坏时保留原数据，并提供恢复默认项目的选择。

## 11. 纸带渲染

- 根据容器宽度计算可见单元数量，保持奇数个单元便于让读写头居中。
- 每个单元使用稳定逻辑位置作为标识。
- 默认以读写头为视图中心；用户手动浏览后暂时关闭自动跟随。
- 纸带写入和移动使用短促动画，但高速模式自动减少或关闭逐步动画。
- 读写头、当前状态与当前位置编号在视觉上形成同一垂直轴。

不建议首版使用 Canvas：DOM 单元更容易编辑、聚焦、读取标签并实现无障碍支持；可见单元数量有限，性能足够。

## 12. 错误模型

错误分为：

- `definition-error`：机器定义无效。
- `duplicate-transition`：相同状态和读取符号存在多条规则。
- `missing-transition`：运行时无匹配规则。
- `step-limit`：达到运行步数上限。
- `invalid-import`：导入文件无效或版本不兼容。
- `storage-error`：本地保存或恢复失败。
- `internal-error`：不应出现的程序错误。

可预期错误在工作台内显示，不使用阻塞式浏览器警告框。内部错误显示简洁提示并保留可供排查的控制台信息，但不得包含用户不相关的浏览器数据。

- 缺少规则与各类终止状态。
- 规则文本解析和错误定位。
- 项目 JSON 往返一致性及版本拒绝。

### 13.2 集成测试

- 编辑规则 → 初始化 → 单步 → 重置完整流程。
- 暂停后继续运行。
- 编辑草稿与运行快照隔离。
- 达到步数限制后可以检查并继续。
- 保存、刷新、恢复。

### 13.3 端到端测试

- 加载一进制加一示例并得到 `1111`。
- 加载二进制加一并验证多个边界输入。
- 导出项目、修改工作台、重新导入并恢复。
- 无效规则阻止运行且定位到对应行或表格单元。
- 键盘完成运行、暂停和单步操作。

## 14. 安全与隐私

- 项目不执行用户输入的 JavaScript；规则仅由受控解析器解释。
- 所有文本用安全 DOM 文本节点渲染，不作为 HTML 注入。
- 导入文件限制合理大小，并限制规则数、状态数、字母表长度和日志长度，防止意外耗尽资源。
- 不请求网络权限，不上传机器配置或纸带内容。

## 15. 建议的首版限制

- 状态数：最多 500。
- 转移规则：最多 10,000 条。
- 单个状态名：最多 64 个字符。
- 纸带符号：一个 Unicode 字素簇。
- 执行日志：内存中最多保留最近 5,000 步。
- 导入文件：最大 5 MB。
- 默认连续运行上限：10,000 步。

限制在界面与导入校验中保持一致，具体数值可在性能测试后调整。

## 16. 发布方式

- 开发阶段通过 Vite 本地服务运行。
- 构建产物输出到 `dist/`。
- 首版目标是静态页面，可部署到 GitHub Pages，也可下载后通过简单本地服务使用。
- 是否强制支持直接双击 `index.html` 离线运行，需在需求确认时决定；Vite 默认构建更适合静态服务器，若必须双击运行，需要采用相对资源路径并验证浏览器文件协议限制。

## 17. 待确认的设计决策

1. 是否批准 TypeScript + Vite + 原生界面方案。
2. 首版是否要求双击 HTML 即可运行，还是接受本地服务/GitHub Pages。
3. 是否首版就加入 Web Worker 高速运行，还是以性能测试结果决定。
4. 项目保存是否只保存初始配置，还是也保存暂停时的完整运行现场。
5. 是否接受首版不提供图形化状态连线编辑器。
