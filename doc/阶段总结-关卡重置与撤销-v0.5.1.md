# 关卡重置与撤销阶段总结 v0.5.1

## 已交付

- 关卡页新增「重置本关」：清空当前关卡的规则草稿，恢复为该关初始提示。
- 已通关的关卡新增「撤销通关」：该关回到「学习中」，可以重新练习。
- 解锁判定由「前面每一关都已完成」改为**前沿式**（序号 ≤ 最远已完成关序号 + 1），
  撤销中间关卡不会锁死已经走到的后续关卡；仍保持一次只能推进一关，不允许跳关。
- 两项操作都用页内 `<dialog>` 确认框，不依赖 `window.confirm`（安卓 WebView 中后者不可靠）。
- 修复 ≤980px 视口下**整页横向溢出**（v0.5.0 起存在的既有缺陷）。

## 架构说明

- `campaign.ts` 仍是纯领域层（无 DOM）。`resetDraft` / `uncompleteLevel` 都是
  「无变化则返回原对象」的纯函数，no-op 分支可被单测直接覆盖。
- 解锁判定只在 `isLevelUnlocked` 一处实现，页面不重复推导 —— 避免出现两套会漂移的规则。
- 确认框用 `<dialog>` + `pendingConfirm` 回调解耦：`close` 事件按 `returnValue` 决定是否执行动作，
  取消与点遮罩都不留副作用。

## 经验沉淀

- **`overflow-x: auto` 挡不住裸 `1fr` 的 min-content 顶穿**：它只对弹性/网格**项目**的自动最小尺寸生效，
  普通块级子元素不受保护。窄屏断点覆盖网格列定义时，必须写成 `minmax(0, 1fr)`，并给可能含长内容的
  网格项补 `min-width: 0`。
- **CDP 窄屏验证必须用 `mobile: false`**：`mobile: true` 会在内容超出时扩张布局视口
  （实测设 `width: 390` 后 `innerWidth` 返回 1560），让「窄屏测试」静默退化成桌面宽度测量；
  测量前应断言 `innerWidth` 是否符合预期，不符合就抛错而非继续。
- v0.5.0 报告里「未执行自动化移动视口截图 / 窄屏规则已通过 CSS 构建检查」这一遗留项**已闭环**：
  CDP 一直具备该能力，当时是用法有误；「CSS 构建检查」也不构成窄屏验收。
