# 图灵机实验台：关卡重置与撤销设计

## 文档信息

- 目标版本：v0.5.1
- 状态：已确认，实施中
- 日期：2026-10-03

## 设计目标

1. 撤销与重置是**纯领域函数**，可单测、与 DOM 解耦。
2. 复用现有进度模型（`CampaignProgress.version = 1`），**不新增存储字段、不做迁移**。
3. 撤销后不产生"玩家被自己锁在门外"的状态：解锁改为前沿式。
4. 确认交互**不依赖 `window.confirm`**：安卓 WebView 外壳未重写 `WebChromeClient.onJsConfirm`，原生 confirm 行为不可靠；改用页内 `<dialog>`，同时便于自动化测试。
5. 两项操作都只作用于当前选中关卡，作用域最小。

## 模块边界

- `src/campaign.ts`（无 DOM / 无 localStorage）
  - 新增 `resetDraft(progress, levelId)`：删除该关草稿键；无草稿时返回原对象。
  - 新增 `uncompleteLevel(progress, levelId)`：把该关从 `completedLevelIds` 移除；未完成时返回原对象。
  - 修改 `isLevelUnlocked(progress, levelId)`：改为前沿式判定。
- `src/campaign-main.ts`
  - 关卡标题区新增「撤销通关」按钮（仅已完成关卡显示）。
  - 「编写规则」区新增「重置本关」按钮。
  - 新增页内 `<dialog>` 确认框与 `askConfirm()` 帮助函数；`window.confirm` 仅作为 `<dialog>` 不可用时的降级。
- `src/campaign-styles.css`
  - 按钮组与确认框样式、窄屏适配。

依赖方向不变：`core.ts → campaign.ts → campaign-main.ts`。

## 数据模型

存储格式**不变**：

```ts
interface CampaignProgress {
  version: 1;
  completedLevelIds: string[];
  drafts: Record<string, string>;
}
```

- 「重置本关」= 删除 `drafts[levelId]`。渲染时 `drafts[id] ?? starter.rules` 自然回落，无需写入初始提示。
- 「撤销通关」= 从 `completedLevelIds` 过滤掉该 id。

## 解锁判定（前沿式）

```ts
export function isLevelUnlocked(progress: CampaignProgress, levelId: string): boolean {
  const index = campaignLevels.findIndex((level) => level.id === levelId);
  if (index < 0) return false;
  const frontier = campaignLevels.reduce(
    (max, level, i) => (progress.completedLevelIds.includes(level.id) ? Math.max(max, i) : max),
    -1,
  );
  return index <= frontier + 1;
}
```

- `frontier = -1`（无完成）→ 只解锁第 1 关。
- `frontier = k` → 解锁到第 `k + 2` 关（即最远已完成关的下一关）。
- 仍保证"一次只能推进一关"，因此不会出现跳关。
- 撤销中间关卡会在集合里留下空洞，前沿式对此天然容错。

**兼容性**：既有单测（初始只解锁第 1 关、完成后解锁下一关、未知 id 返回 false、`completeLevel` 对未解锁关 no-op）在本公式下全部保持原结论。

## 界面

- 关卡标题行：`第 N / 16 关` + 通关状态徽标；已完成时状态徽标旁出现「撤销通关」。
- 「编写规则」卡片标题行：右侧「草稿会自动保存」旁新增「重置本关」。
- 两处点击都先进入页内确认框（`<dialog>` + `<form method="dialog">`）：
  - 取消 / Esc / 点遮罩 → 关闭且不执行；
  - 「确认」按钮 `value="confirm"` → 关闭后执行对应动作。
- 动作执行后调用 `render()` 重绘，并把结果提示写入 `aria-live` 区域。

## 错误与兼容

- `localStorage` 写入失败时沿用既有 `saveProgress()` 返回的告警文案，不阻断操作。
- `<dialog>.showModal` 不可用时降级为 `window.confirm`（返回 `true` 才执行）。
- 旧进度含空洞或未知 id 时，`normalizeCampaignProgress` 与前沿式解锁都不会抛错。
- 不读、不写自由实验项目；不改变关卡内容与参考答案。
