## 关键风险与对策
- **Form C 绝对路径白屏**：构建用 `vite build --base=./`（CLI 覆盖，不改 `vite.config.ts`）。自检：`grep -oE '(src|href)="[^"]+"' dist/index.html` 不应出现以 `/` 开头的资源路径。
- **gradlew CRLF**：根 `.gitattributes` 钉 `android/gradlew text eol=lf`。
- **Kotlin 常量前向引用**：`ASSET_DOMAIN` 必须先于 `PAGE_URL` 声明（模板已正确排序，照搬即可）。
- **CI 看不到日志**：workflow 内置把 `^e:` 错误写成 `::error` 注解；查状态用 `curl` + GitHub API 而非 WebFetch（有 15 分钟缓存）。

## 版本说明
- 网页最新发布为 `v0.3.0`（GitHub Release 已存在），APK 作为同源新分发，故 APK `versionName=0.3.1`、tag 用 `v0.3.1`，不占用 `v0.3.0`。

## 签名修复（2026-09-28）

v0.3.1 的 APK 由 CI 现场生成的随机 debug 证书签发，私钥未保存 ——
装了 v0.3.1 的用户无法覆盖升级（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）。
本次补上固定签名基线，并顺带修掉两个让门禁失效的配置缺陷：

- [x] 生成 PKCS12 `android/app/debug.keystore` 并入库；`.gitattributes` 补 `*.keystore binary`
- [x] `build.gradle.kts` 加 `signingConfigs { getByName("debug") }`，显式 `storeType = "PKCS12"`
- [x] `tests/android-shell.test.js`：加签名断言（4 条）；`versionName` 改为与 `package.json` 对齐；
      补 assets 缺失时的 `SKIP` 逻辑与两条守卫 —— 用例 8 → 11
- [x] `ci.yml` 追加 `sync:android` + `test:android` —— 该测试此前**从未在 CI 执行过**
      （被 `vite.config.ts` 的 `test.exclude` 排除在 vitest 之外，又没有人显式调用它）
- [x] `ci.yml` 触发分支 `[main]` → `["**"]`；`android-apk.yml` 补 `"android-apk"` 分支
      —— 此前 `android-apk` 上 15 个提交未受任何检查
- [x] 核对线上 v0.3.1：证书 subject 为 AGP 默认模板、notBefore 与 CI 运行时刻只差约 2 分钟，
      实证为随机签名；新 keystore 证书指纹 `E0:1C:75:3D:…`
- [ ] **发版**：`versionCode` 升到 ≥ 2、`versionName` 按目标版本同步，打 tag 触发 Release
