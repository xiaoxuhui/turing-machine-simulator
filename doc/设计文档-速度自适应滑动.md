# 设计文档：跟随读写头模式的滑动时长随速度自适应

## 现状
- `src/main.ts` `renderTape()` 在 `follow-head` 分支用 `tape.style.transition = "transform 150ms ease-out"` 触发滑动。
- 运行节奏来自 `src/execution-scheduler.ts`：每 16ms tick 一次，按 `credit += elapsedMs * 速度 / 1000` 累积步数；即单步间隔 ≈ `1000 / 速度` 毫秒。

## 设计
- D1 纯函数 `slideDurationMs(stepsPerSecond)`（放 `src/core.ts`，可单测）：
  - 先对速度做安全夹紧：`speed = clamp(stepsPerSecond, 1, 1000)`（NaN/非法 → 1）。
  - `interval = 1000 / speed`（单步间隔，毫秒）。
  - 返回 `clamp(interval * 0.9, 8, 900)`：
    - 上限 900：极慢速也不会滑得过长；
    - 下限 8：快速时短到几乎瞬时，避免超过步进间隔造成积压；
    - 系数 0.9：滑动占满约 9 成间隔，慢速连续、快速跟手。
- D2 `renderTape` 的 `follow-head` 分支用 `slideDurationMs(Number(value("speed")))` 动态生成过渡时长，替换硬编码 `150ms`。
- D3 非跟随分支（固定 0 / 随意拖动）维持 `transition = "none"`，不受影响。
- D4 速度在运行中改变时，下一次 `renderTape` 即时采用新时长，无需额外接线。

## 取舍
- 用「目标速度」而非「实际速度」驱动时长：目标速度正是调度器计算步进间隔的依据，二者天然同步；且目标速度始终可读、稳定。
- 固定系数 0.9 已在慢/快两端都满足需求，不做更复杂的曲线。
