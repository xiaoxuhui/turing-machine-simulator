# 设计文档：跟随读写头视角平滑移动

## 现状
`renderTape()` 计算 `center = tapeWindowCenter(mode, head) + effectiveTapeScroll(mode, tapeScroll)`，
以 `center±8` 渲染 17 个单元格。在 `follow-head` 下 `center === head`，每步 `head` 变化即整段重渲染，
纸带瞬间跳到新中心。

`#tape` 的 `transform` 当前仅由「随意拖动」的 `applyShift` 使用（亚格跟手）。

## 设计
复用「随意拖动」验证过的平滑思路，但触发条件改为「中心相对上次渲染变化」：

1. **纯函数 `headFollowShift(fromCenter, toCenter, pitch)`**：返回 `(toCenter - fromCenter) * pitch`，
   即把新渲染的纸带瞬时移回旧中心所需的像素位移。该函数可单测，与渲染解耦。
2. **`renderTape` 动画块（仅 `follow-head`）**：
   - 若 `tapeRenderCenter !== null` 且 `center !== tapeRenderCenter`：
     - `transition = none` + `transform = translateX(shift)`（瞬时把新 cells 放到旧中心位置）；
     - 强制重排 `void tape.offsetWidth`；
     - `transition = transform 150ms ease-out` + `transform = translateX(0)`（滑回新中心）。
   - 每次渲染后记录 `tapeRenderCenter = center`。
3. **非跟随模式**：不累积跟随偏移；并把 `transition` 清为 `none`，保证「随意拖动」即时跟手不被遗留过渡拖慢。
4. **防跳变初始化**：`createMachine` / `resetMachine` / 切视角时把 `tapeRenderCenter` 置 `null`，
   并清除 `#tape` 的 `transform` 与 `transition`，使首次渲染直接定位、不滑入。

## 为什么连续而非累积
每帧都「瞬时位移→过渡回 0」，且 cells 同时推进一格，因此上一帧目标（新中心）== 下一帧起点（旧中心位移），
视觉上连续；即便运行速度很快（每 tick 多步），也只是滑得更远，不会回弹。

## 影响面
- `core.ts`：新增 `headFollowShift`。
- `main.ts`：新增模块态 `tapeRenderCenter`；`renderTape` 增加动画分支与清理分支；
  `createMachine`/`resetMachine`/切视角处重置。
- `styles.css`：无需改动（过渡以 inline style 设置，`will-change: transform` 已存在）。
