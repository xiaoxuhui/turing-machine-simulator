# 图灵机实验台 v0.2.0：重构需求与测试用例

## 文档状态

- 版本：v0.2.0
- 状态：实施中
- 日期：2026-08-27
- 依据：现有《需求文档》《设计文档》与 `CODE_REVIEW.md`

## 一、重构目标

在不改变现有图灵机语义、项目 JSON v1、快捷键和用户操作流程的前提下，降低 `main.ts` 的职责密度，修复全路线后台任务的可达崩溃路径，并建立可独立测试的运行调度与路线任务边界。

## 二、功能需求

### R01 路线任务稳定性

- 任意采样帧都不得通过超长参数展开调用 `Math.min/Math.max`。
- Worker 出错时必须恢复“后台生成”按钮、禁用“取消”按钮并显示中文错误。
- 取消、完成、失败三种结束路径必须统一清理 Worker。

### R02 主界面职责拆分

- 连续运行的时间片、目标速度、实际速度测量移入独立调度模块。
- 全路线 Worker 生命周期、进度和结果移入独立控制器。
- `main.ts` 保留应用装配和跨模块协调，不再直接实现上述底层循环。

### R03 行为兼容

- 单步、运行、暂停、重置与 1–1000 步/秒调速保持现有行为。
- 全路线仍支持任意正整数步数、后台运行、进度、取消和压缩显示。
- 一进制加一、二进制加一、回文判断和忙碌海狸示例结果不得改变。

## 三、单元测试用例

| 编号 | 输入/操作 | 期望结果 |
| --- | --- | --- |
| U01 | 路线边界扫描 150,000 个位置 | 返回正确最小/最大位置且不抛栈溢出 |
| U02 | 路线任务 complete | 控制器清理 Worker 并恢复按钮 |
| U03 | 路线任务 error | 显示错误、清理 Worker并恢复按钮 |
| U04 | 速度目标 1000，经过 16ms | 调度器计算应执行的批量步数 |
| U05 | 调度器暂停后再次启动 | 时间和步数统计从新会话重新计算 |
| U06 | 二进制加一 `1011` | 停机后得到 `1100` |
| U07 | 回文示例 `1001` | 进入接受状态 |
| U08 | 忙碌海狸默认输入 | 产生固定步数和纸带结果 |

- 本轮不重写整个规则编辑器与瓷砖界面。
