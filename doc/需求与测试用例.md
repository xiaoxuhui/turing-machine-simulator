## 一、重构目标

在不改变图灵机语义、项目 JSON v1、无限正整数路线步数和既有操作流程的前提下，消除用户输入注入与异步竞态风险，建立原子导入边界，并补齐可公开协作所需的工程文件。许可证由仓库所有者确认后单独加入。

## 二、功能需求

### R01 安全文本渲染

- 执行日志中的状态名、读写符号和方向必须通过文本节点渲染。
- 规则中即使包含 HTML 标签或事件属性文本，也不得创建对应 DOM 元素或执行脚本。

### R02 原子项目导入与可靠存储

- JSON 必须先完成结构、版本、数值范围和规则语义校验，再替换当前工作台。
- 无效、截断或未来版本项目不得部分覆盖当前输入。
- localStorage 不可用或超额时，页面保持可用并显示可恢复错误。

### R03 异步与交互稳定性

- 已被新路线任务替换的 Worker 即使迟到回调，也不得清理或覆盖新任务。
- 拼图使用无偏 Fisher–Yates 洗牌，并允许测试注入随机源。
- 焦点位于按钮时，空格键只触发浏览器原生点击一次。

### R04 开源工程可协作性

- CI 在受支持 Node 版本执行测试与生产构建。
- README、贡献指南、安全报告、行为准则、Issue 与 PR 模板相互一致。
- 包版本、仓库地址、运行要求和命令与实际工程一致。
- 未选择许可证前明确标注“尚不可按开源许可证再分发”，不得伪称已完成开源授权。
