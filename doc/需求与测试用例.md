# 图灵机实验台 v0.3.0：开源整改需求与测试用例

## 2026-10-24 补充：吉斯维杰特数列图灵机转换器

- 状态：规划中；本节优先于早期“后台数列计算器”草案。
- U01：在实验台输入整数阈值 `T`，点击“开始转换”后，转移规则出现在原有规则编辑器中；转换过程不得计算或预填数列项。
- U02：机器从首项 `1` 开始；空白符为 `0`，只在纸带的未写入格显示 `0`。
- U03：运行/单步由现有 `TuringMachine` 解释转移规则。对已有前缀计算最大重复后缀次数，写入下一项。
- U04：写入值等于 `T` 时继续；首次写入值严格大于 `T` 时停机，并保留这个超阈值项。
- U05：非法阈值不改变当前规则、输入和机器；转换后的规则可查看和编辑。
- U06：对 `T=1,2,3` 验证停机位置与完整纸带，至少包含 `T=3` 时第 220 项为 `4` 的用例。
- U07（2026-10-24 补充）：保留直接计算和图灵机计算两种模式。直接计算可写下一项、生成到指定项数、取消、重置；切换模式不重置任一模式的当前进度。
- U08：直接计算用后台线程保持页面可操作，直接结果和机器纸带独立；0 只作未写入占位。

## 一、重构目标

在不改变图灵机语义、项目 JSON v1、无限正整数路线步数和既有操作流程的前提下，消除用户输入注入与异步竞态风险，建立原子导入边界，并补齐可公开协作所需的工程文件。许可证由仓库所有者确认后单独加入。

## 二、功能需求

### R01 安全文本渲染

- 执行日志中的状态名、读写符号和方向必须通过文本节点渲染。
- 规则中即使包含 HTML 标签或事件属性文本，也不得创建对应 DOM 元素或执行脚本。

### R02 原子项目导入与可靠存储

- JSON 必须先完成结构、版本、数值范围和规则语义校验，再替换当前工作台。
- 无效、截断或未来版本项目不得部分覆盖当前输入。
- localStorage 不可用或超额时，页面保持可用并显示可恢复错误。

### R03 异步与交互稳定性

- 已被新路线任务替换的 Worker 即使迟到回调，也不得清理或覆盖新任务。
- 拼图使用无偏 Fisher–Yates 洗牌，并允许测试注入随机源。
- 焦点位于按钮时，空格键只触发浏览器原生点击一次。

### R04 开源工程可协作性

- CI 在受支持 Node 版本执行测试与生产构建。
- README、贡献指南、安全报告、行为准则、Issue 与 PR 模板相互一致。
- 包版本、仓库地址、运行要求和命令与实际工程一致。
- 未选择许可证前明确标注“尚不可按开源许可证再分发”，不得伪称已完成开源授权。

## 三、单元测试用例

| 编号 | 输入/操作 | 期望结果 |
| --- | --- | --- |
| U01 | 日志字段为 `<img src=x onerror=...>` | 输出仍为纯文本，不创建 HTML |
| U02 | 导入字段缺失、类型错误或 version > 1 | 拒绝且给出可读错误 |
| U03 | 导入含重复转移规则 | 在替换工作台前拒绝 |

| U06 | 二进制加一 `1011` | 停机后得到 `1100` |
| U07 | 回文示例 `1001` | 进入接受状态 |
| U08 | 旧版项目 JSON v1 | 成功导入且行为不变 |

## 五、兼容与非目标

- 保持项目 JSON v1 和 localStorage 键兼容。
- 不重新加入路线步数硬上限；超大任务继续允许后台取消和并行操作。
- 不重写整个规则编辑器和瓷砖界面，不改图灵机数学语义。
- 本轮不发布、不推送、不打标签；许可证和远端分支修复需仓库所有者另行确认。
