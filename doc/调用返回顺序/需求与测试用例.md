# 调用返回顺序修正

- 日期：2026-10-28；状态：已批准。用户要求删除顺序调用覆盖返回路径的优先逻辑。
- 问题：顶格调用被收集后，除最后一次外强行接到下一个函数，跳过用户定义的外部退出规则。
- 需求：每次顶格调用都保留明确写出的外部退出路径；仅无外部退出规则时沿用连续调用。普通规则仍按状态和符号匹配，位置不决定逐行执行。

| 用例 | 预期 |
| --- | --- |
| U01 | `r; q1→HALT; r` 的第一次 r 退出即执行 q1，不先执行第二个 r |
| U02 | 返回状态缺少当前符号规则时明确报缺规则，不跳去下一个函数 |
| U03 | 外部规则经 q2 显式调用 r 时遵循该跳转，状态路径为 q1、q2、r 内部入口、q1 |
| U04 | 公开退出状态的外部规则也不被后续裸名调用覆盖 |
| U05 | 无外部退出规则的重复调用、组合函数及全部 8 个教程保持结果 |

用户当前程序中 q2 再次转向 r 会形成状态循环；修复不删除用户写出的循环，也不改写用户草稿。
