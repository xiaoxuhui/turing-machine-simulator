# 调用返回顺序修正

- 日期：2026-10-28；状态：已批准。用户要求删除顺序调用覆盖返回路径的优先逻辑。
- 问题：顶格调用被收集后，除最后一次外强行接到下一个函数，跳过用户定义的外部退出规则。
- 最终需求：从第一个顶格调用开始，保留源码中的调用与表达式顺序。函数完成后执行调用行下面的表达式；表达式下一状态为函数名时，调用完成后继续该表达式下面。相邻同状态规则是按读取符号选择的分支，不重复执行。函数定义只声明，不执行。

| 用例 | 预期 |
| --- | --- |
| U01 | `r; q1→HALT; r` 的第一次 r 退出即执行 q1，不先执行第二个 r |
| U02 | 返回状态缺少当前符号规则时明确报缺规则，不跳去下一个函数 |
| U03 | 用户程序依次执行 r、q1 分支、q2 调用 r、最后一行 r，共 5 步停机；不回到上面的 q1 循环 |
| U04 | 公开退出状态的外部规则也不被后续裸名调用覆盖 |
| U05 | 无外部退出规则的重复调用、组合函数及全部 8 个教程保持结果 |

第一个调用之前的顶格规则保留为既有状态声明，纯转移规则程序保持原语义。修复不改写用户草稿。

用户随后补充的最终规则：

- U06：函数体内 `ret q1`（兼容 `返回状态 q1`）才声明跳到外部对应状态；正常完成接下一行，不根据第二个参数自动跳出。`导出状态` 单独用于公开状态。
- U07：填写的初始状态/函数优先；空值才选择第一个调用。选择第二个函数不能再运行第一个；未知入口不自动回退。
- U08：原有 8 个教程改用新写法；返回例保留 ret 输出 12，删除 ret 输出 19，两者各 3 步。
- U09：使用用户完整 r/f 程序（tests/fixtures/function-calls-no-ret.tm），空纸带、空白符 0、初始状态 a1、停机态 H，8 步停机；a1/a2 可跳到后面的 d1/d2，函数返回调用位置而非函数定义内的行。
- U10：新增实际名称面板，展示每个源码状态及函数实例对应的真实名称、实际入口、转换后规则；编辑时同步，输出可选中复制且不会修改源码。
- U11：按用户要求，函数示例源码和实际规则输出不带注释；说明只在示例介绍与独立映射区域显示。
