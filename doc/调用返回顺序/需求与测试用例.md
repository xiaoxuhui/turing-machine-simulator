# 调用返回顺序修正

- 日期：2026-10-28；状态：已批准。用户要求删除顺序调用覆盖返回路径的优先逻辑。
- 问题：顶格调用被收集后，除最后一次外强行接到下一个函数，跳过用户定义的外部退出规则。
- 最终需求：从第一个顶格调用开始，保留源码中的调用与表达式顺序。函数完成后执行调用行下面的表达式；表达式下一状态为函数名时，调用完成后继续该表达式下面。相邻同状态规则是按读取符号选择的分支，不重复执行。函数定义只声明，不执行。

| 用例 | 预期 |
| --- | --- |
| U01 | `r; q1→HALT; r` 的第一次 r 退出即执行 q1，不先执行第二个 r |
| U02 | 返回状态缺少当前符号规则时明确报缺规则，不跳去下一个函数 |
| U03 | 用户程序依次执行 r、q1 分支、q2 调用 r、最后一行 r，共 5 步停机；不回到上面的 q1 循环 |
| U04 | 公开退出状态的外部规则也不被后续裸名调用覆盖 |
| U05 | 无外部退出规则的重复调用、组合函数及全部 8 个教程保持结果 |

第一个调用之前的顶格规则保留为既有状态声明，纯转移规则程序保持原语义。修复不改写用户草稿。
