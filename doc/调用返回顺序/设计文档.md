# 调用返回顺序设计

- 日期：2026-10-28；状态：实施中。沿用 plan-driven-frontend-dev 流程。
- 第一个顶格调用及后面的规则按源代码行号合并为执行序列，不再单独抽出所有函数名。相邻同状态规则合为一个分支组；选中一条后继续查找后面的匹配状态组或调用，不返回已越过的行。
- 为每个表达式组生成独立状态，函数静态展开后的退出指向下一个表达式或调用。表达式调用函数时，续接点是该表达式后面的源码位置。终态显式停止，匹配状态缺少读取分支仍报错。
- 调用前的状态规则保留为声明，以兼容已有程序；没有调用时仍是普通状态图。组合函数内部调用列表按顺序执行，公开扩展声明和命名隔离保留。
- 不改 TuringMachine 单步运行或终态语义。更新页面与 README，把“调用列表顺序”和“规则按状态匹配”说清楚。
