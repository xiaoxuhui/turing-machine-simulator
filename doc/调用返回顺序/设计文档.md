# 调用返回顺序设计

- 日期：2026-10-28；状态：已完成。沿用 plan-driven-frontend-dev 流程。
- 第一个顶格调用及后面的规则按源代码行号合并为执行序列，不再单独抽出所有函数名。相邻同状态规则合为一个分支组；选中一条后继续查找后面的匹配状态组或调用，不返回已越过的行。
- 为每个表达式组生成独立状态，函数静态展开后的退出指向下一个表达式或调用。表达式调用函数时，续接点是该表达式后面的源码位置。终态显式停止，匹配状态缺少读取分支仍报错。
- 调用前的状态规则保留为声明，以兼容已有程序；没有调用时仍是普通状态图。组合函数内部调用列表按顺序执行，公开扩展声明和命名隔离保留。
- 不改 TuringMachine 单步运行或终态语义。更新页面与 README，把“调用列表顺序”和“规则按状态匹配”说清楚。
- 先用回归测试复现，再验证修复和原有教程；独立浏览器上下文检验教程、ret 与正常续行、初始入口，保留用户原页面草稿。

最终补充：`ret` 是函数体内的返回状态声明，到达所声明状态才跳入外部同名状态或父函数对应状态，未到达不跳出；普通完成仅续行。`返回状态` 作为 ret 的中文兼容写法，`导出状态` 保留公开引用作用，两者分开。返回目标随调用上下文隔离，并展开为普通转移，不增加隐藏执行步。

`ParseResult.sourceEntries` 记录源码中的函数调用/表达式入口。初始状态非空时按名称选择相应入口、函数、公开状态或普通状态；仅空白值采用第一个调用的默认入口。显式填写未知状态保留缺规则反馈。

用户完整程序复现出声明区跳到后面表达式标签时未映射内部名称的问题，已补齐标签别名。显式状态跳转定位命名表达式，函数正常完成才按调用位置续行；声明区末尾调用续接第一个源码调用。

实际名称面板使用编译器产生的 internalNames 元数据，记录源码名、实例入口、实际名；不从生成字符串反推。显示最终解析后的入口和普通转移文本，默认折叠，展开时生成长文本。原有表格继续只读展示规则。
