# 需求与测试用例：目标速度手动输入

## 背景
当前「目标速度」只能靠滑杆（`#speed`，1–1000 步/秒）调节，范围大、难精确命中（如想设 137 步/秒）。
用户反馈滑杆“太不好控制”。

## 需求
- R1 **新增数字输入框**：在目标速度滑杆旁新增一个 `<input type="number">`，可手动键入精确步/秒。
- R2 **双向同步**：滑块改动 → 同步数字框与文案；数字框改动 → 同步滑块与文案。二者始终一致。
- R3 **补充而非替换**：数字框是滑杆的**补充**（添加），滑杆保留，不删除。
- R4 **规范化一致**：数字框输入越界/空/非法时，沿用 `normalizeSpeed` 的 1–1000 夹紧与取整规则，与滑块行为一致。
- R5 加载/保存工程时，目标速度仍从滑块读取，数字框随滑块同步显示。

## 测试用例
- T1 键入数字框 137 → 滑块值=137、文案=`137 步/秒`、数字框值=137。
- T2 拖动滑块到 50 → 数字框值=50、文案=`50 步/秒`。
- T3 数字框输入 5000（越界）→ 规范为 1000，滑块=数字框=1000。
- T4 数字框输入空/非法 → 规范为下限 1（空串 Number("")=0→max(1,0)=1），不崩溃。
- T5 滑块与数字框任一改动都不会造成无限循环（程序化设值不触发 input 事件）。
