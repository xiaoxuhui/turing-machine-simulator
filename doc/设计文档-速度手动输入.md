# 设计文档：目标速度手动输入

## 现状
`.speed` 区只有滑杆 `#speed`(range,1–1000) + `#speedText` 文案 + `#actualSpeed`。
`updateSpeedText()` 读滑杆值 → `normalizeSpeed` → 写回滑杆 + 文案。滑杆难精确命中目标值。

## 设计
新增数字框 `#speedNumber`（type=number, min=1, max=1000），与滑块并存。

### 模块 `src/speed-input.ts`
- `interface SpeedSyncElements { slider; number; text }`
- `applySpeed(els, raw)`：规范化后同时写 `els.slider.value`、`els.number.value`、`els.text.textContent`，单一事实来源。
- `attachSpeedSync(els)`：给滑块与数字框各挂 `input` 监听，二者都调 `applySpeed(els, Number(对应框.value))`。
  - 程序化设 `.value` 不会触发 `input` 事件 → 双向同步无死循环。

### 宿主接线 `main.ts`
- 定义 `const speedEls = { slider: byId("speed"), number: byId("speedNumber"), text: byId("speedText") }`。
- `updateSpeedText()` 改为 `applySpeed(speedEls, Number(speedEls.slider.value))`（保留旧调用点：载入工程、初始化）。
- 用 `attachSpeedSync(speedEls)` 替换原 `byId("speed").addEventListener("input", updateSpeedText)`。
- 载入工程（line 149）设滑块值后 `updateSpeedText()` 自动同步数字框。

### 样式 `styles.css`
- `.speed input[type="number"] { width: 72px; padding: 6px 8px; border: 1px solid #dfe5ed; border-radius: 8px; }`，与 `.view-mode select` 风格一致。

## 影响面
- 不改动 `normalizeSpeed` / `execution-scheduler` / `project-codec` 的校验规则。
- 仅扩展 UI 控件，行为向后兼容（滑块仍可用）。
